# QQBot-service

独立 QQ 业务服务：**NapCat（OneBot 11）+ 本机 Sub2API**。实现聊天、只读文件分析、公开视频转换、长回复合并转发和加密文件回传。指定管理员名单从旧部署迁移；不继承QQ群管理员身份。

> 当前：代码、离线测试、网关调用和服务启动已完成；QQ扫码登录及实际群/私聊收发仍待验收。详情见 `docs/mcp-deployment-20260921.md`。

## 日常使用

- 双击 `启动机器人.cmd`：启动或复用本项目的 NapCat、业务服务，不停止普通 QQ。
- 双击 `打开登录页面.cmd`：打开本机登录页面。用机器人 QQ 扫码。
- 停止：`powershell -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1`。仅停止匹配本项目路径的进程。
- 健康状态：`http://127.0.0.1:3002/healthz`。`ok=true` 只代表业务进程存活，QQ可用还要求 `onebot_connected=true`、`qq_online=true`。
- 登录面板：本机端口6099，仅loopback监听，访问token由本机脚本读取，不贴入群聊。

## 普通用户

| 使用方式 | 行为 |
| --- | --- |
| 群内 `@机器人 问题` | 当前群模型回复；默认不对所有闲聊自动插话 |
| 好友私聊直接发文字 | 与群聊相同的对话能力，不需要@ |
| 上传文件 | 自动只读分析，支持文本、PDF、docx、xlsx、pptx；不支持扫描PDF OCR、旧版doc/xls/ppt、执行程序 |
| 支持的视频链接/含链接的小程序卡片 | 优先B站、抖音、小红书；成功后作为原生视频发回原会话；同一群同视频10分钟内只转发一次 |
| 群友语录（本群开关启用后） | 指定管理员回复一条纯文字群消息并发送「计入」；在本群 @该群友 语录，随机收到一张根据其原话生成的图片卡片，不附带额外文字消息；编号在图片底部；不调用大模型 |
| `/下载 https://公开文件地址` | 下载文件后加密ZIP回传，不访问内网或任意本机文件 |
| `/打包` | 将自己在当前会话最近上传/下载的文件加密回传 |
| 文件同时配文字 `/打包` | 将该消息所附文件分别加密回传（最多3个） |
| `/导出` | 将自己在本会话最近的模型答案导出为加密ZIP中的Markdown |
| `/重置` | 清除自己在当前会话的上下文，不影响其他人 |
| `/帮助` | 显示指令 |

普通聊天只有在 Bot 成功生成且收到发送成功回执后才计为有效互动。达到至少 10 轮、横跨至少 3 个自然日后，才启用当前会话下该用户的结构化长期记忆；只保存筛选后的事实、偏好、项目或事件摘要，不把完整聊天正文写入长期记忆表。命令、关键词人设回复、文件/视频任务和发送失败不计入门槛。

超长文字以合并转发聊天记录发送，不截断正文。QQ仍可能限制大合并转发或账号发送，失败不会被记为成功。

ZIP格式为AES-256，随机12位密码。文件名示例：`报告_密码-aB3cD4eF5gH6.zip`，密码也在同会话提示。Windows默认解压器可能不支持，应使用7-Zip/WinRAR。**密码与文件一起发送只能满足传输格式要求，不能对同一会话的其他人保密。**

## 指定管理员

- `/模型列表`：读取当前Sub2API模型列表。
- `/模型`：查看当前会话模型。
- `/模型 完整模型ID`：切换当前群或私聊模型。
- `/默认模型 完整模型ID`：修改没有单独设置模型的会话默认值。
- `/角色`、`/角色列表`：查看角色；群聊中设置本群角色后，该角色卡覆盖本群全部普通文字聊天回复（命令、文件/视频任务除外）；管理员私聊可设置供各群回落和私聊关键词使用的全局默认角色；`/角色 默认` 恢复默认层级。
- `/记忆 状态`、`/记忆 查看 <用户QQ号>`：查看原会话的长期记忆统计或指定用户档案；仅指定 Bot 管理员可用，结果只发送给请求管理员的 QQ 私聊。私聊失败不回退群聊，存量敏感记忆显示为「内容已隐藏」。
- `/人格状态`：查看当前会话角色卡的本人状态名、群氛围、关系档位与 OOC 重试/风格告警/兜底计数；仅指定 Bot 管理员可用，只输出状态名与计数。
- `/嘲讽`、`/嘲讽 温和|标准|辛辣|默认`：查看或设置小杂鱼的嘲讽强度（默认“温和”）；群里设置只影响本群，私聊设置全局默认；仅指定管理员可用。
- `/状态`：连接、当前模型及任务计数。
- `/任务`：当前会话最近10个任务ID和状态。
- `/重发 任务ID`：显式重发失败/待确认任务中尚未确认成功的部分，只能发回原会话；记忆查询、私聊结果及视频任务不允许重发，防止泄露或重复转发。
- `/能力` 查看本会话开关；`/开 视频`、`/关 视频` 为总开关，`/开 B站转发`、`/关 B站转发`、`/开 小红书转发`、`/关 小红书转发` 分别控制本群对应平台，默认保持开启；抖音仍受总开关控制。
- `/开 语录`、`/关 语录`：仅指定管理员在群里控制本群语录功能，**所有群默认关闭**，管理员私聊不会自动开启群语录。
- `/语录 状态`：查看本群使用方法；`/语录 删除 <编号>`：指定管理员或被收录的本人删除一条；`/语录 退出`：群友删除自己在本群的语录并拒绝今后收录；`/语录 恢复`：重新允许后续收录，不恢复已删除内容。群友可在本群查询随机语录，其他群不能跨群查询。
- 人设回复按本地规则把消息分为技术/情绪/身份/越界等意图：求助类嘴上嫌弃、手上帮忙（先嫌一句再给关键做法），情绪先接住并用否认式关心、不拿难过开玩笑，被夸得意收下、示爱不接，身份首次打岔、严肃追问口吻化承认，越界在角色内拒绝；模型失败时按问题类型走对应兜底。
- `/启用`、`/停用`：控制本会话普通用户功能。
- `/群触发 @`、`/群触发 全部`：设置本群聊天触发。文件/视频自动处理独立于此开关。

没有 `/run`、任意Shell或本机任意文件访问。P10/P11仅在本机显式开启后提供白名单工具和需二次确认的指定应用管理；管理员名单唯一来自本机配置，群主/群管理员和聊天自称管理员均不提权。

## 配置与凭据

- `config.json`：本机专用，不提交版本控制。
- 出口防护 safe_net 用公共 DoH（1.1.1.1、223.5.5.5，IP 字面直连）做解析兜底：本机开启代理 fake-IP/TUN 模式后仍能解析平台域名；内网、保留地址和云元数据依旧全部拦截，且只在系统解析整体不可用时才启用。
- Sub2API Key 从 `F:/Apps/Sub2API/native/.gwkey-current` 读取，不复制进源码。
- 当前已验证默认模型：`deepseek-v4-flash-ga-260731`。其他列表项需要使用时再验证；不自动更改网关账号或渠道。
- 管理员模型和角色选择、长期记忆档案持久化在 `state/bot.sqlite3`。内置角色卡位于 `persona_cards/roles/`；长期记忆按 `scope + owner` 隔离。
- 修改OneBot token时需要同步 `../NapCat-runtime/napcat/config/onebot11.json` 和登录后生成的账号配置，再重启对应服务。
- 需要平台登录时，在 `cookie_files` 中配置自己有权使用的 Netscape cookies 文件路径，键为 `bilibili`、`douyin`、`xiaohongshu`。不要发送Cookie给群友；程序不会主动提取浏览器Cookie。
- 对于无公开视频URL的小程序、私密/付费/DRM内容、图文笔记、整合集或直播，不保证转换，也不绕过限制。

默认限制：30MB文件、150MB视频、视频20分钟、每用户每日100次接受的请求、每用户最多3个待处理任务、总待处理40个。文件和历史默认24小时清理；每10分钟执行一次过期清理。忙碌/超限事件目前静默拒绝以防刷屏。

日志：`logs/service.log`，不记录用户正文或密钥。诊断QQ平台问题时还需查看NapCat本机日志，注意其中可能含扫码登录信息和访问token，不要公开粘贴原始日志。

## P8 主动聊天（默认关闭）

仅 `config.admins` 中指定管理员可在目标群执行 `/主动 开`、`/主动 关`、`/主动 状态`。群主/群管理员身份不会提权。`/停用` 或关闭「聊天」能力同样抑制主动参与；私聊不支持主动。

- 话题插话：最近 5 分钟至少 4 条、至少 2 位用户的群消息，规则通过后按角色概率决定；刚被动处理过的群有短暂避让。
- 冷场找话：本次进程内观察到群消息后，默认静默 1 小时可尝试；重启不加载群聊天正文，因此需要群内新活动重新建立窗口。
- 关系触发：本群已达到长期记忆互动门槛的熟悉用户出现时采用角色关系概率，不读取私聊记忆，不增加其互动轮数。
- 每群每天最多 6 次主动尝试（失败、跳过和不明投递也占额度），间隔至少 15 分钟，本机时间 00:00–08:00 静默。连续 2 次无人回应后概率降到原来的 1/4，3 次则当日暂停；隔天恢复，开关切换不会清空预算。
- 回应口径：投递尝试后的 120 秒内出现一条普通用户文字视作回应；超过窗口结算无人回应。不是语义级“回复给 Bot”判定。投递失败保守视作可能送达，不自动重试。
- 群窗口只驻内存，最多 128 群、每群 8 条、每条 160 字，默认 5 分钟过期；不存额外完整群聊日志，不读取个人历史。只有最终生成的输出沿用原 outbox/receipt 持久化。
- `config.json` 可选 `social` 段：`daily_limit`、`cooldown_seconds`、`quiet_start`、`quiet_end`、`idle_seconds`、`window_seconds`、`topic_min`、`response_seconds`、`probe_seconds`。缺省即安全默认值；额度不能超过 6，冷却/概率探测至少 900 秒，静默小时相同表示关闭时段限制。配置重启生效。
- 角色 `card.json` 的 `social_behavior` 注入主动判断和生成，`social_policy` 提供 `enabled/topic/idle/relationship` 意愿与概率参数；不在引擎内写死角色名。模型可输出 `<SKIP>` 放弃，不增加额外判断调用。
- 主动输出只走纯文本发送，不进入命令、下载或工具入口；含命令前缀、CQ、@ 或 HTTP 链接的生成结果直接丢弃。未知投递不自动重发。

实现和验证详情见 `docs/mcp-p8-proactive-chat.md`。源码交付默认不自动启用任何真实群。


## P9～P14 连续阶段交付

这些阶段的源码和离线回归已完成；本轮**未重启生产服务、未启用真实群/工具/应用控制、未提交或合并 main**。不要把代码已写入当作当前运行进程已加载。汇总与逐阶段报告入口：`docs/mcp-p9-p14-delivery.md`。

### P9 知识库

先由指定管理员在目标会话上传 txt/md/pdf/docx/xlsx/pptx，再执行 `/知识库 导入 [namespace]`。只读取本人当前会话最近文件，经既有 work 路径和受限抽取流程。群内只能导入 `group:<本群号>`；私聊默认 `common`，可显式 `role:<角色ID>`。`/知识库 状态`、`/知识库 列表`、`/知识库 删除 <id>`、`/知识库 重建 <id>` 用于管理。

仅明确导入的资料进入知识库，不自动收聊天、记忆或日志。当前角色 `knowledge_namespaces` 可收窄但不能扩大程序权限。采用中文双字分词的 SQLite FTS5/BM25 本地检索，不依赖云端embedding；近义改写召回有限。每来源40000字、每空间100份；检索4条、单条800字、总注入2400字。知识内容始终是非可信参考，不是操作授权。

### P10 受控工具

配置 `tool_calling_enabled: true` 和 `tool_models: ["已验证支持工具协议的模型ID"]` 才启用普通聊天工具协议；旧配置不变。不在文件分析、关键词或主动聊天中开启工具。首批 get_time、get_bot_status、get_model_list、search_memory、search_knowledge、get_recent_files；其中状态/模型列表维持管理员权限，记忆/文件仅限本人当前范围，文件不返回路径。

Broker严格校验权限、scope、schema、风险与频率；单消息最多3次、同工具失败不重试、最多2个执行槽。L0超时线程不能强杀但持续占槽，不开放任意执行。工具调用失败只返回安全错误码。

### P11 指定应用

`controlled-apps.example.json` 是**可选配置片段，不是可覆盖整个 config.json 的完整配置**。默认 `app_control_enabled: false`；由本机操作者确认脚本路径、动作、scope、宿主和超时后再合入配置。它仅示例 QQBot/NapCat/Sub2API，后续应用必须手工白名单加入。

命令 `/应用 状态|启动|停止|重启 <app_id>`；变更一律先返回120秒票据，**同一指定管理员、同一会话**发送 `/应用 确认 <票据>` 才执行。模型无确认工具。票据一次性且绑定白名单版本；撤权、改配置、过期均拒绝。QQBot仅示例状态/标准自重启，不把会同时停止NapCat的原 stop.ps1 当作单Bot停止。Sub2API蓝绿轮换超时可能仍在进行，未知结果不能自动重试。不要直接在生产群中做启停验收。

### P12 模型容灾

顶层可选配置 `model_pool`、`failure_threshold`（2）、`cooldown_seconds`（120）、`probe_interval`（300）、`probe_success_threshold`（2）。没有备用池时不自动切换、不付费探测。模型ID必须来自实际验证，示例不替操作者猜测账号或模型。

连续明确网关失败达到阈值后串行切备用；scope+owner粘性；后台低频probe达到成功阈值才回主。业务拒绝/投递失败不切换。读超时或普通连接中断按未知结果处理，不重放；只有明确连接超时、503/网关5xx、明确无账号类错误触发既定策略。工具已有执行时，不跨模型重放同一工具对话。

### P13 并发

`workers` 可选配置默认为 `{"chat":2,"file":1,"media":1,"tool":1}`，保守上限4/2/1/1；模型生成和恢复探测全局2槽。不同用户可以并行，同scope+owner任务保持顺序；视频或应用控制不会因共用单worker阻塞其他人的聊天。每job多段输出保持连续，较早运行chat有投递屏障。SQLite继续WAL，只有限重试未成功SQL；processing/sending重启分别为interrupted/unknown，不重新跑已付费任务。

生产main先获取服务文件租约和loopback健康端口，再创建Bot/Store；第二实例（包括旧版本服务还占端口的情况）不会先误执行数据库恢复。自重启仍复用原标准脚本。

### P14 运行观测

管理员 `/状态` 展示每日量、队列、模型/角色/主动/工具指标和worker平均耗时，最长1350字；WARN/CRITICAL只识别不额外群通知。`tools/report-metrics.py --days 1|7|30 [--json]` 用只读SQLite导出，不影响在途任务。聚合保留90天、工具审计30天、过期确认票据额外保留24小时。指标没有QQ号/scope、正文、Prompt/回复、文件内容或凭据；模型/角色/工具标签为本机HMAC指纹，离线不做明文用户分析。不提供公网Dashboard或 `/metrics`。

全新表均增量创建，旧业务表与数据保留。升级前应使用SQLite在线备份或先安全停止后备份数据库（不要只复制一个正在WAL写入的主文件），并保留原配置。默认不启用额外外部能力，验收后按既有重启流程加载源码即可；回滚源码不必删除新表。
