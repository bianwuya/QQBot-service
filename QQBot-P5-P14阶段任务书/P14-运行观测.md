# P14：运行观测与指标

## 目标

建立不泄漏聊天正文的运行观测层，回答：

- Bot 今天处理了多少消息？
- 哪个模型最不稳定？
- 主动聊天有没有被回应？
- 哪个人格使用最多？
- Tool 调用是否经常失败？
- Chat / File / Media 平均耗时是多少？

---

## 1. 指标范围

建议至少包含：

### 系统
```text
uptime
queue_depth
jobs_total
jobs_failed
jobs_interrupted
delivery_unknown
```

### 模型
```text
model_requests
model_failures
model_switches
avg_latency
health_state
```

### Persona
```text
role_usage
ooc_hits
fallback_count
retry_count
```

### Social
```text
proactive_attempts
proactive_sent
proactive_replied
daily_suppressed
```

### Tools
```text
tool_calls
tool_success
tool_failure
tool_timeout
confirm_required
```

### Worker
```text
chat_latency
file_latency
media_latency
tool_latency
```

---

## 2. 隐私

严禁指标系统保存：

- 消息正文；
- Prompt 全文；
- 模型回复全文；
- Token；
- 密码；
- QQ 号明文（如需用户维度，使用不可逆或受控标识）；
- 文件正文。

---

## 3. 存储

可以新增：

```text
metrics_daily
metrics_events
```

但不要把每一条消息都存成巨量明细。

优先：
- 聚合计数；
- 有限审计事件；
- 定期归档。

---

## 4. `/状态` 增强

管理员 `/状态` 建议输出：

```text
运行时间
今日消息
队列长度

模型状态
当前主模型
备用模型
最近切换原因

人格统计
主动聊天统计
工具统计
平均耗时
```

输出控制在适合 QQ 阅读的长度。

---

## 5. 离线统计

建议新增：

```text
tools/report-metrics.py
```

可输出：
- 今日；
- 最近 7 天；
- 最近 30 天。

第一版输出文本/JSON 即可，不做 Web Dashboard。

---

## 6. 告警

第一版只做状态识别，不需要复杂通知系统。

可以标记：

```text
WARN
CRITICAL
```

例如：
- 连续模型失败；
- unknown delivery 增长；
- media worker 长时间卡死；
- tool failure 异常升高。

---

## 7. 测试

至少覆盖：

1. 普通消息计数；
2. 模型失败计数；
3. 模型切换计数；
4. persona 使用统计；
5. social 统计；
6. tool 统计；
7. worker latency；
8. `/状态` 权限；
9. 指标不包含消息正文；
10. 指标不包含 Token；
11. 聚合跨日；
12. 老数据库兼容。

---

## 8. 不允许做的事

- 不做 Web 公网 Dashboard。
- 不暴露 `/metrics` 到公网。
- 不记录完整 Prompt。
- 不记录完整模型回复。
- 不上传第三方分析平台。
- 不为统计破坏现有隐私边界。

---

## 9. 完成标准

- 关键运行数据可查询；
- `/状态` 明显增强；
- 有离线统计脚本；
- 能观察模型、Persona、Social、Tools、Workers；
- 不保存敏感正文；
- 原测试 + 新测试全部通过。
