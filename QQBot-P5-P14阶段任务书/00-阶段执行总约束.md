# QQBot-service 后续阶段执行总约束

> 适用阶段：P5 ～ P14  
> 目标：让 Codex / 主 Agent 每次只处理当前阶段，禁止提前读取、提前实现、顺手重构后续阶段内容。

## 1. 最重要的执行规则

1. **一次只执行一个阶段。**
   - 当前阶段由操作者明确指定，例如：`执行 P5`。
   - 未被指定的阶段一律视为“未来需求”，不得实现。
   - 不允许因为“顺手”“以后会用到”“这样架构更漂亮”而提前实现后续阶段。

2. **一次只读取一个阶段任务书。**
   - 执行 P5 时，只允许读取：
     - `00-阶段执行总约束.md`
     - `P5-回复清洗与输出管线.md`
     - 当前工程源码、测试、现有项目文档
   - **禁止读取 P6～P14 的任务书。**
   - 执行 P6 时同理，只读取总约束 + P6。
   - 未来阶段文件存在的目的只是排期，不是当前上下文。

3. **当前阶段任务书是唯一需求源。**
   - 不根据未来任务书推测接口。
   - 不预埋未来功能。
   - 不为了未来阶段修改当前无关模块。
   - 如果当前阶段确实需要新增接口，只实现当前阶段明确需要的最小接口。

4. **必须保持现有功能兼容。**
   - 除当前任务书明确要求改变的行为外，现有行为不得改变。
   - 已存在的命令、权限、限流、文件/视频能力、发送回执、崩溃恢复、安全边界必须保持。
   - 不得因为重构而改变管理员权限来源。
   - 不得让群主/群管理员获得原本没有的权限。

5. **禁止大爆炸式重构。**
   - 每阶段只做本阶段需要的最小结构调整。
   - 优先“新增模块 + 迁移有限职责”，避免一次性重写 `app.py`、`protocol.py`、`store.py`。
   - 如果发现历史代码问题但不属于当前阶段：
     - 记录到“发现但不处理”章节；
     - 不在当前阶段顺手修。

---

## 2. 当前工程基线必须保留

以下约束除非某一阶段任务书明确要求修改，否则全部继续成立：

- Windows 本机部署目录：`F:\Apps\QQBot-service`
- OneBot / Sub2API 均为本机回环服务。
- SQLite 为主持久层，继续使用 WAL。
- 模型不得直接获得任意本机工具权限。
- QQBot 管理员权限唯一来源仍为 `config.admins`。
- 群主、群管理员身份本身不提权。
- 下载继续受 `safe_net` 约束。
- 出站文件继续加密。
- 日志不得记录消息正文、Token、敏感凭据。
- 崩溃恢复原则继续保持“不自动重跑已付费模型调用、不自动重发未知投递”。
- 同一 `scope + owner` 的聊天语义必须保持有序。
- 所有新增数据库字段/表必须支持旧库平滑升级。
- 不允许删除现有数据。
- 不允许把未来阶段需要的数据结构一次性全部加入数据库。

---

## 3. 每个阶段的标准执行流程

执行当前阶段时严格按以下顺序：

### A. 读取
只读取：
1. 本文件；
2. 当前阶段任务书；
3. 与当前任务直接相关的源码和测试；
4. 当前工程已有架构说明。

### B. 先给出改造计划
开始改代码前，先列出：
- 将修改哪些文件；
- 将新增哪些文件；
- 每个改动解决什么问题；
- 哪些现有行为必须保持不变。

如果任务书中没有要求，不得扩大范围。

### C. 实现
- 尽量小步提交。
- 新逻辑优先放入独立模块。
- 所有关键边界必须有测试。
- 禁止通过修改测试来掩盖功能回归。
- 禁止删除原测试。

### D. 本地验证
至少执行：
```powershell
.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests
```

如果当前阶段任务书指定了额外测试，也必须执行。

### E. 输出阶段报告
完成后必须给出：

```text
阶段：
状态：完成 / 部分完成 / 阻塞

新增文件：
修改文件：

实现内容：
1.
2.
3.

兼容性：
- 原功能是否保持
- 数据库是否兼容
- 配置是否兼容

测试：
- 原测试：
- 新增测试：
- 总测试结果：

发现但未处理：
- 仅记录不属于本阶段的问题

下一步：
- 只写“等待人工验收并合入 main”
- 不自动进入下一阶段
```

## 4. 阶段结束规则

当前阶段完成后：

- **立即停止。**
- 不读取下一阶段任务书。
- 不生成下一阶段代码。
- 不修改下一阶段配置。
- 不创建下一阶段数据库结构。
- 不“顺手”补未来能力。

只有在操作者明确回复类似：

```text
P5 已合入 main，开始 P6
```

之后，才允许读取 `P6-*.md`。

---

## 5. 阻塞处理规则

如果当前阶段出现无法安全决定的问题：

1. 不猜；
2. 不自行扩大设计；
3. 输出最多 3 个可选方案；
4. 清楚说明每个方案对当前阶段的影响；
5. 等操作者选择后继续。

如果问题不影响本阶段核心目标，则：
- 采用最保守、最兼容的方案；
- 在阶段报告中记录。

---

## 6. 禁止事项

禁止：

- 一次读取全部 P5～P14 任务书。
- 为未来阶段预先实现 RAG、Tool Calling、主动聊天、并发 Worker 等。
- 把模型直接接到 shell / PowerShell / 任意文件系统接口。
- 绕过 `config.admins` 权限模型。
- 为方便开发关闭 `safe_net`。
- 把聊天正文写入日志。
- 删除旧数据库或用“重建数据库”代替迁移。
- 修改与当前阶段无关的行为。
- 为追求“整洁”进行大规模无关重构。
- 当前阶段完成后自动进入下一阶段。

---

## 7. 验收原则

一个阶段只有同时满足以下条件才算完成：

- 当前阶段功能完成；
- 旧功能无明显回归；
- 旧测试全部通过；
- 当前阶段新增测试通过；
- 数据迁移可回滚或兼容；
- 配置兼容；
- 日志无敏感信息泄漏；
- 未提前实现未来阶段。

如果其中任何一项未满足，阶段状态必须标记为“部分完成”或“阻塞”。
