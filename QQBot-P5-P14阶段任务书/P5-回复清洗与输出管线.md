# P5：回复清洗与输出管线

## 目标

把所有“模型生成文本”统一经过一个可测试的输出处理层，减少 Markdown 残留、奇怪符号、AI 腔、重复内容和人格出戏，同时不能破坏代码、URL、普通标点或现有发送逻辑。

本阶段只做“输出处理”，**不做多角色卡、不做长期记忆、不做主动聊天、不做 RAG、不做 Function Calling。**

---

## 1. 新增模块

建议新增：

```text
reply_pipeline.py
```

职责只包含：
- 文本分类；
- Markdown/格式清洗；
- 异常文本检测；
- 重复内容处理；
- 长度规范；
- OOC/禁用短语检测接口；
- 必要时返回“需要重新生成”的信号。

不要在这里直接调用 OneBot，也不要直接操作数据库。

---

## 2. 需要接入的输出路径

至少统一覆盖：

1. 普通聊天模型输出；
2. 关键词人格模型输出；
3. 自定义 `gen` 命令模型输出；
4. 模型失败后的文本兜底应保持可控，但无需强制二次清洗已有纯文本 fallback。

固定文本命令不需要走复杂模型清洗，只需保证发送层不被破坏。

---

## 3. 清洗策略

### 3.1 保护区域

必须先识别并保护：

- fenced code block：三反引号代码块；
- inline code；
- URL；
- 文件路径；
- JSON / Python / Shell 中合法的 `*`、`_`、`#`、反引号等符号。

不能使用“全局删除特殊字符”的实现。

### 3.2 普通文本可处理内容

允许清理：

- `**粗体**` → `粗体`
- `__强调__` → `强调`
- 多余标题符号；
- 无意义的连续 `#`；
- 连续 3 行以上空行压缩；
- 行尾多余空格；
- 明显模型模板前缀，例如：
  - “作为AI……”
  - “以下是我的回答……”
  - “根据你的要求……”
  - “当然可以，以下是……”

AI 腔检测必须只作用于普通聊天/角色聊天，不要误删真实引用或代码内容。

### 3.3 重复检测

实现轻量级重复检测：

- 连续完全重复句去重；
- 同一句连续出现 2 次以上时只保留一次；
- 不做复杂语义去重；
- 不调用额外模型。

### 3.4 长度处理

保留现有发送层的“>1400 字合并转发”规则。

Reply Pipeline 不替代发送分片。

它只负责：
- 去掉异常超长尾巴；
- 可配置最大生成文本长度；
- 不直接把长回答截成 1400。

---

## 4. OOC 统一接口

现有关键词人格已有 OOC 检测。

本阶段把 OOC 检测封装成可复用接口，但不要改变现有人格内容。

目标：

```text
check_output(text, context_type) -> result
```

至少区分：

```text
normal_chat
persona_chat
custom_gen
```

如果人格输出命中明确 OOC：
- 首次：允许触发一次重生成；
- 再次失败：使用现有 fallback；
- 每次消息最多重生成 1 次，避免费用失控。

普通聊天只处理非常明显的 AI 自述，不进行人格风格判断。

---

## 5. 建议接口

可以采用类似：

```python
class ReplyResult:
    text: str
    retry: bool
    reason: str | None
```

以及：

```python
clean_reply(...)
validate_reply(...)
process_reply(...)
```

具体命名允许根据现有代码风格调整。

---

## 6. 配置

如确有需要，可以增加少量配置，但优先使用代码内默认值。

禁止为了本阶段加入大型配置系统。

允许的配置示例：

```text
reply_max_chars
reply_retry_on_ooc
```

必须有默认值，旧 `config.json` 无需修改即可启动。

---

## 7. 测试要求

新增测试至少覆盖：

1. 普通 Markdown 粗体被清理；
2. 代码块中的 `**` 不被破坏；
3. URL 不被破坏；
4. JSON 内容不被误删；
5. 连续空行压缩；
6. 连续重复句去重；
7. 明显 AI 腔被识别；
8. persona OOC 只重试一次；
9. 重试后仍失败走 fallback；
10. 普通聊天、自定义 gen、关键词人格都经过新管线；
11. 固定文本命令行为不变；
12. >1400 字发送策略仍由原发送逻辑处理。

---

## 8. 不允许做的事

- 不迁移 `persona.py` 到角色卡。
- 不新增角色切换命令。
- 不新增长期记忆表。
- 不新增主动发言。
- 不新增 RAG。
- 不新增工具调用。
- 不修改模型路由。
- 不做 Worker 并发。
- 不大改 `app.py`，只做接入新输出层所需的最小修改。

---

## 9. 完成标准

P5 完成时应满足：

- 所有模型文本进入统一 Reply Pipeline；
- 代码/URL/结构化文本不被破坏；
- 常见 Markdown 脏格式明显减少；
- 明显 AI 腔有统一检测；
- persona OOC 具备单次重试；
- 原有全部测试通过；
- 新增测试通过；
- 不包含 P6 及后续功能。
