状态：实现与离线验证完成；未修改Sub2API、未配置真实备用池、未做真实付费探测。

## 变更与行为

新增 `model_router.py`、`tests/test_model_router.py`；修改 `protocol.py` 的结构化上游错误和 `app.py` 的路由入口/后台探测/状态命令。计划见 `docs/mcp-p12-plan.md`。

可选配置为 model_pool（模型ID列表）、failure_threshold（默认2）、cooldown_seconds（120）、probe_interval（300）、probe_success_threshold（2）。没有备用池则严格走原单模型调用，无后台探测。各生成路径使用scope+owner粘性；手动 `/模型` 清理本scope粘性，`/默认模型` 清全部；配置候选变化也重选。

HEALTHY→DEGRADED→COOLDOWN→PROBING→HEALTHY。单次503只降级不立即熔断；达到阈值后串行尝试备用，连接超时可直接熔断；一次请求至多查看3个候选，不并发竞速。备用成功后粘住，主模型仅后台低频probe恢复，连续成功达到阈值才回归。`/状态` 显示候选状态、当前会话模型和安全原因码，无账号信息。

允许分类：503/500/502/504、明确no_available_accounts类错误、连接超时/连接错误。普通Rejected、提示拒绝、OneBot投递失败不切换；读超时标记response_unknown，不自动重放。一次工具对话已有任何工具执行时，后续模型失败也不切换重放工具。进程重启仍沿用原Store的“不重跑已处理/未知投递”语义。

## 问题与取舍

- 未按错误文本模糊匹配普通Rejected，防止业务拒绝被误当上游故障；只使用结构化错误类别。
- 不以用户请求高频试探恢复，独立低频维护线程只探测一个已熔断模型；这不是并发Worker或模型竞速。
- 健康和粘性为有界内存（64模型、1024会话），进程重启清空；不把用户提示写入路由状态。
- 备用列表需操作者提供已验证模型ID；本轮不擅自猜测或购买模型，也不改生产网关。
