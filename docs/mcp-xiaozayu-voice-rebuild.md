# 小杂鱼声线重构：从傻白甜回到有锋芒的人物

## 症结与设计

- 原 `card.json` 强化“被夸三拍必破防”“元气/♡/~”等标签，`corpus.json` 的日常、脆弱和兜底语料把模型牵向撒娇；这不是仅加一句“不要傻白甜”能解决的。
- 原 `examples_for` 无论技术求助、情绪支持还是身份提问，都先抽取日常、挑衅、得意或害羞示例。原 `persona_answer` 出戏后拿同一份 prompt 重试，无法主动纠偏。
- 人设保留“嚣张、心虚、渴望被关注”的矛盾，但补足行动原则：抓对方原话里的具体细节、好胜而不辱人、被抓错会补救、关心给具体行动、真被夸只失神半拍而非三轮持续卖萌。她不是对任何话题都反撩或总说“杂鱼”。

## 实现

- 只改 `xiaozayu` 角色卡及通用采样/守卫逻辑，不改变 `normal` 的人设。语料改为多种反应：试探、争胜、认输、收拾场面、认真关心；不用甜腻的固定开场白。
- 闲聊保留角色示例；任务型意图不混入挑衅/害羞示例。夸奖当轮允许短暂停顿，后续仍在原三轮状态桶中，但示例改为回神和继续过招，正经求助仍优先任务。
- 收窄“可爱”等宽泛触发；意图分类、关系与状态共用触发判断，不把第三人称“他喜欢你”误算为针对 Bot 的夸奖。普通“怎么/为什么”不再一概当技术求助。
- 在角色卡配置甜腻语气规则；闲聊命中时沿原有一次重试/兜底流程，但重试会明确追加具体纠偏要求。情绪支持不受甜腻过滤误杀；硬安全和身份诚实约束保持不变。
- `app.py` 原有私聊普通助手、媒体路径及群角色选择机制不在此改动范围。旧历史回复只作为事实上下文，不作为新声线模板；首次互动标作“初次”，不虚构上次见面或现实动作。更新运行中的进程前需按项目既有发布流程重启服务；不在验证脚本中对 QQ 发送消息。

## 背景与来源

参考对“杂鱼”式挑衅角色的公开讨论：核心表演力来自快速抓破绽、过度自信与能力落差，而非堆砌口癖或一味撒娇（[角色分析](https://note.com/kazamaturi_siki/n/nc7d7baa68b9c?hl=en)）。本项目按全年龄群聊另行处理，不引入该题材中涉及未成年或色情的元素。设计与安全边界以仓库现有角色卡及用户反馈为准。
