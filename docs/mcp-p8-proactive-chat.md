## 3. 实现内容

### 开关与权限

升级群和新群均默认关闭。仅 `config.admins` 指定管理员可在群里执行：

```text
/主动 开
/主动 关
/主动 状态
```

群主/群管理员不自动提权。私聊拒绝启用。会话停用或关闭聊天能力时，主动任务也被抑制。切换开关不重置预算和当天暂停状态。

### 三种触发

1. 话题插话：默认最近 300 秒至少 4 条、至少两位发言者，最新消息 60 秒内且未被被动路径处理。
2. 冷场找话：本进程观察到群活动后，默认 3600 秒无新活动时可尝试；不从旧群历史恢复窗口。
3. 关系触发：最近发言用户在本群达到既有长期记忆互动门槛时，使用角色的关系概率；不读取其私聊历史。

所有触发先过规则，再按角色概率抽样。被动处理过的群至少避让 120 秒；概率未命中也间隔至少 900 秒再探测，避免逐条消息重复抽样。模型判断与生成合并为一次调用：不适宜就输出 `<SKIP>`。不做额外的逐消息模型判断或付费重试。

### 角色与预算

- 始终解析当前群角色；`social_behavior` 注入主动参与判断和语气规则。
- `social_policy` 明确表达意愿和概率，无角色名硬编码。通用角色 topic/idle/relationship = 0.15/0.10/0.25；小杂鱼 = 0.25/0.15/0.40；旧卡缺省有保守回退。
- 每群每天最多 6 次尝试，至少 900 秒间隔，本机时区 00:00–08:00 静默。不是保证每天说满 6 次。
- 模型调用前持久化预算。失败、跳过、输出过滤和未知投递均不退额度，以保守控制成本。
- 120 秒回应窗口内出现普通用户文字算回应；超过窗口结算无人回应。连续 2 次无人回应后概率乘 0.25，连续 3 次后当天暂停；次日本地自然日恢复。
- 不声称做语义级“用户是否在回应 Bot”识别；这是有明确口径的规则近似。
- 配置仅新增可选 `social` 段，缺省兼容；具体参数见 `README.md`。日上限和冷却有安全上界/下界，配置不能放大到超过 6 次或缩短到 15 分钟以下。

### 上下文、执行与投递

- 群窗口只驻内存，最多 128 群，每群 8 条，每条 160 字，默认 300 秒有效；不落额外完整消息日志。
- 群窗口不包含私聊历史、命令或媒体内容，不把用户 ID 加入模型上下文。
- 原 worker 没有排队任务时，scheduler 每 30 秒最多安排一次尝试；不新增 worker，不改变被动任务处理顺序。
- 使用既有 jobs/outbox/receipt。持久任务载荷只有群路由和内部主动标记，不保存观测窗口；最终模型输出仍按原投递协议存储。
- 主动结果不进入 `process`、命令、自定义指令、下载或工具路径，只能发送一个 text 段；过滤命令前缀、CQ、@ 和 HTTP 链接，OOC 丢弃，不付费重试。
- 自己的消息由既有 normalize 入口拒绝，引擎再防一层，不会自回复循环。
- 发送前复核群开关、角色、群活动版本、在线状态、静默时段和日期；生成中变更则取消过期输出。
- queued 状态的崩溃残留主动任务不重新执行；processing 按原 Store 标记 interrupted，sending 按原 Store 标记 unknown，不自动重跑模型或重发未知投递。
- 主动输出不计入普通互动轮数，不写个人历史、关系或长期记忆。

## 4. 中途问题与已处理项

1. 发现如果“发出第三条”就立即按无人回应暂停，会误伤随后及时回应的用户：改为 120 秒窗口到期后再结算，补第三条及时回应和跨日测试。
2. 模型生成期间可能进入静默时段、群消息已经更新、群开关或角色已改变：添加发送前复核，补动态取消测试。群活动使用消息标识，不以同一秒的时间戳判断新旧。
3. 仅用内存冷却会在重启/开关切换后绕过预算：日额度、最近尝试、待回应和暂停状态复用 settings 持久化；开关不清预算，补重启与并发预占测试。
4. 崩溃若发生在 accept 与 processing 之间可能留下 queued 主动任务：worker 明确识别并终止这种残留，不把内部事件当普通聊天执行。
5. 过期窗口在静默或限额状态可能留存较久：scheduler 枚举阶段同样清理过期正文和已停用群，另设全局群数上限。
6. 终端 Git diff 使用了分页器导致命令等待：已退出分页器并改用 `git --no-pager diff`，没有改动用户 Git 配置。

## 7. 发现但未处理 / 已知取舍

- 保持单 worker 架构：已开始的一次主动模型调用会占用该 worker，新到被动任务需等待；只在空闲启动且无重试，未越界进行并发重构。
- 群窗口重启后清空，冷场功能要等该群出现新活动才能重新建立；默认关闭或未观察过的群不会凭空主动。
- 群中任何新活动都可能使生成中的主动内容作废；活跃群采用保守取消策略，减少过时插话，成本仍计入尝试预算。
- 关系触发使用既有结构化熟悉度门槛，不实现新的关系状态机。
- P7.1 的人工验收及 main 合并状态仍由操作者处理，本轮没有冒充验收。
